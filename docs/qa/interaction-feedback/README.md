# 双骰、抽卡详情、聊天布局和事件说明

2026-10-27。对应本轮五项交互／CI 优化。保留服务端随机和结算，客户端仅消费已确认公开事件。

## 实现

- 坏时钟的 `ability-dice.faces` 原有两枚结果被表现层过滤，页面只显示后续单骰确认。现在两枚骰子同盘投出，分别确认点数，显示“取较小值”或“双同点相加”的基础移动；后续 `roll` 确认跨快照／刷新不再生成一次新投掷。慈善家的双骰也可使用同一批次表现，选择使用骰不会重投；骰子先生的六骰和双方决斗仍沿用各自规则。
- 已向当前玩家开放的角色候选卡增加独立“详情 · 技能”按钮，使用现有角色详情弹窗。开关详情不会发出选择动作或改变选择 ID；观战者继续只看到等待状态。覆盖蛋抽卡，以及使用角色 ID 的其他能力选择。
- 桌面聊天锚定在小地图实际下沿，采用同宽侧栏；只观察小地图，不测技能面板。场景延迟加载时等待小地图出现后安装 ResizeObserver。短横屏分列展示选择、小地图和聊天；手机保留键盘避让。候选数量变化、展开／关闭聊天、发送消息均不让聊天上下跳。
- 决斗家事件骰显示掷骰选手、同格发动来源、指定点数及不符后果。`rollReason` 是公开说明，随骰子任务保存，早期三角人触发骰和最终记录均能携带；旧记录缺字段时显示事件规则说明。随机与绊倒条件沿用原结算。
- 默认 CI 的必要项目与手动专项以[测试范围](../../testing.md)为唯一说明。快速单元每项只执行一次；默认保留 9 项交互、9 项 relay 助手和一场八人联机，长浏览器矩阵移至手动 `all`。

## 本地验证

- `pnpm typecheck` 通过。
- `pnpm test`：**1316/1316** 通过。
- `pnpm build`：客户端、Node 服务端和浏览器主机包通过；`pnpm exec wrangler deploy --dry-run` 通过。
- 真实 Edge 的 **9/9** 项交互通过：坏时钟不同点／同点，桌面／手机三张候选逐项打开技能、关闭再选择和观战隐私，决斗事件骰原因，八人布局下 1280×900、1024×768、390×844、900×500 的聊天／小地图／选择面板避让及手机键盘桥接。
- CI=true 软件 WebGL **13/13** 通过，包含上述 9 项及原有六骰选点不重投、六骰三角人因果、单技能骰和双人决斗。默认范围已用 `--list` 核对为 9 项交互、9 项 relay 助手、1 项八人单场。

第一轮真实浏览器为 7/9：短横屏的地图位置被延迟加载的同优先级 CSS 覆盖，修正父级选择器并给选择面板留出横向空间后通过；决斗检查原先误读了下一回合已恢复的最终状态，改为检查已公开绊倒事件及其对应 DOM 演出后通过。短时骰面、数量和说明由操作前安装的 MutationObserver 留存，避免 Node 轮询迟到造成假失败。

手机为 Windows Edge 视口模拟，未进行实体手机 GPU 测试。本地未重复八人长局；远端 CI、自动预览及正式发布均须以各自实际状态为准，本说明不作为部署成功证明。
