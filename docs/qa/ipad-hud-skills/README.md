# iPad 比赛布局与技能选择

平板宽度下，原先固定在顶部的状态条会与相机按钮、房主暂停说明重叠。651–1366px 且高度至少 571px 的视口现在为顶部按钮、相机工具栏、状态与赛事说明分别留出空间；顶部内容换行和赛事收放后，位置按实际高度更新。

平板聊天移到左下方，宽度由 252px 增至 310–360px，高度最多 400px。聊天上方避让赛事说明，底部保留角色条；打开聊天或出现新消息时，技能选项使用右侧空间，保留完整小地图。键盘弹出时减少底部留白，输入框和发送区继续可用。技能选项的长短不决定聊天锚点。

电灯泡没有合法双人格时，直接继续主骰，不再显示只有“不使用”的选择。有合法目标时仍可传送或放弃，传送后照常进行主移动。只修改当前规则引擎，历史版本保留。

吸盘鱼特殊赛事原本支持从起点带人，本次没有改规则。新增回归实证：起点三人同格，第一人掷出 3 后选择带第二人，位置变为 `[3,3,0]`；第二人回合掷出 2 后选择带回第一人，位置变为 `[5,5,0]`。两个选择均经过 JSON 保存恢复，移动日志保持同组行动。每次仅携带一人，带人者先到达；仍须每次选择，传送和零移动不触发。

## 验证

- 完整 `pnpm test`：1457/1457 通过，含电灯泡 4 项与吸盘鱼赛事新增 3 项回归。
- `pnpm typecheck`、`pnpm build`、`pnpm exec wrangler deploy --dry-run`：通过；构建仍有原有的大 chunk 提示。
- 顶部与聊天浏览器：9/9 通过，覆盖 768×1024、820×1180、1024×768、1180×820、1366×1024，以及既有桌面、手机和短横屏。
- 既有技能比较、抽卡详情、双骰和特殊赛事浏览器：11/11 通过，覆盖桌面/手机实际选择、刷新、私密信息边界和三会话赛事响应。
- 房主与客人分别检查顶部按钮、场次信息、相机栏、倒计时、赛事面板与小地图两两不相交，赛事和镜头设置收起/展开后重验，实际按钮及镜头复选框中心可点击。镜头设置使用正常布局，展开后会推下状态与赛事区域。
- 聊天验证短/长技能选项、实际消息发送、连续三条新消息、地图/技能不相交、底部角色详情入口可点击；手机及 1024×768 均模拟 300px 键盘偏移并检查输入框位置与点击命中。

第一轮 1024×768 实测聊天记录区只有 62.5px，未达到阅读空间要求。改为较宽平板的暂停说明与按钮同行，重新运行上述 9 项全部通过，记录区大于 80px；没有放宽断言。键盘模拟检查的是布局桥接，不代表实体 iPad Safari 测试。没有新增或手动触发远端工作流。
