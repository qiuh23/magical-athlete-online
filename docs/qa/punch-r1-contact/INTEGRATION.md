# Finite r1 contact runtime contract

The production adapter is in `src/client/scene/Board3D.tsx`. This is a newly rebuilt, bounded controller, not a restoration of the lost tested tree or permission to reactivate legacy Punch contact plans. Checkpoint identifiers in the source QA records refer to local reconstruction checkpoints, not public commit links.

- Normal game entry enables the released scene while preserving explicit query overrides. The new r1 layer is limited to Wild23 and Wild24. It remains hidden until the rebuilt environment, current approved-pad load, non-Punch assets and certified rig are ready; an independent sticky r1 load failure cannot be overwritten by another loader's success.
- Controller identity includes the existing room/backend/round/content scope plus environment retry, mechanism retry and renderer reset. Cache retry replaces the controller/layer. Late loading cannot restart an already-consumed beat.
- The real Pawn body is statically bound before taking its actual geometry snapshot, including its base/cap and authored sculpture transforms. Async fingerprint results use a generation and capture-key guard. Cleanup invalidates both the Trip and r1 consumers. Pending, failed or unfreezable geometry cannot authorize contact.
- The same `PresentationClock` and pause state drive the layer and Pawn. The layer samples before Pawn through the existing R3F frame loop. No new permanent animation loop is introduced.
- A validated r1 route takes priority over legacy Punch and ordinary gait timing. The real `pawnRoute` is built from the actual event path and occupancy offsets. `r1ActorPosition` applies the already-transformed route, the existing stride and the .005 surface offset exactly once. Its world XYZ is assigned directly, without a second compact rotation, stride lift or local-to-world conversion. Static body yaw and real occupancy scale are unchanged.
- While a validated r1 action owns the route, extra skeletal motion and unrelated move/skill sway are suppressed. Cancellation or rig failure does not invent a new rule result or abandon the actual route. Existing down/recovery behavior remains separate.
- `tests/punch-r1-board-integration.test.ts` inspects the real adapter AST and its readiness/clock/snapshot wiring. Controller tests use real engine event fixtures and 650/850/1700 ms windows. These checks do not claim a live WebGL component rendering test.

The finite allowlist contains 12 exact trajectories: Wild23 forward and Wild24 backward, desktop and compact, banana full/economy and Coach full. Unknown geometry, Coach economy, altered forms/mounts, already-down targets, crowds, nearby moving actors, concurrent targets, arbitrary spacing/paths and short or late windows remain real event cues. The original rules and authoritative positions are unchanged.
