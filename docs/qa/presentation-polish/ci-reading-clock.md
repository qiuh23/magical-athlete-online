# PR #25 的 CI 骰子结果阅读时钟修复

## 失败证据

- 失败提交：`8589e3b83c7c0c0935f883716a0a91a16f18819b`。
- [Checks #135](https://github.com/qiuh23/magical-athlete-online/actions/runs/40216207779)，verify job `121237764009` 的第 19 步：11 项定向浏览器检查中 8 项通过、3 项失败。类型、固定单元、构建、Worker dry-run 均先通过；后续八人检查尚未执行。
- 三角人与 NPC 连锁分别停在“确认 3 点”的短时 DOM 断言；游荡巨口用例在截图后等待技能横幅，已错过该阶段。
- 原普通单骰在 2500ms 动画的 84% 才显示数字，结果最多只有约 400ms；显示结果与完成动画使用两个独立定时器。主线程卡顿跨过两个截止点时，结果可直接被下一阶段覆盖。
- 确定性复现：在旧构建投骰开始后阻塞主线程 3 秒。普通模式与减少动画/8 倍速两项均失败，浏览器内 `MutationObserver` 只记录到 `dice(face="") → skill → move`，没有确认 3 的 DOM。因此问题并非仅是 Node 轮询漏采。

## 修复

- 数字结果提交后，经过一次绘制机会再确认当前骰子的事件 key。表现队列从这次确认开始保留单骰 1000ms、六骰 1800ms、决斗 1500ms 的最短阅读期；原动画结束时间不能跳过尚未显示的结果。
- 同一事件只确认一次；新快照不重置阅读期。换事件、跳过、重连和重新启用时清理旧状态。只改本地表现时钟，不推进服务端规则。
- 短时断言改为操作前安装的浏览器 DOM 观察记录：点数、角色头像、事件 ID、棋子旧位置和场地标记必须在同一条记录中匹配，随后严格验证技能、移动和最终位置。
- 截图不再占用待检查的短时阶段；失败时将公开事件与 DOM 序列写入 test-results 的 JSON 并附加到报告，供 CI 产物下载。
