# 维尼／钱袋先生联动与场地事件结算顺序

2026-10-27。检查并修复当前 events-v1 引擎；旧规则版本的冻结引擎未改。新增必要规则回归沿用现有 `pnpm test`，CI 工作流与远端浏览器选择范围保持不变。

## 联动结论

钱袋先生付费替代掷骰属于一次能力发动，完整主移动及其后果完成后通知能力观察者。同回合只有这一次能力时，维尼不移动；例如再有粘液修正完成，累计达到两次，维尼前进 1 格。拒绝、没有积分或被阻止的钱袋技能不算一次已完成能力，不制造额外骰子。

维尼保留项目既有适配：每回合从第二次能力完成起，每次完成前进 1，自己的这类响应不计数；立即起身也不递归触发自己。Extra Mile 原卡“多个能力”没有详细说明跨包、嵌套和完成时机，这一数字适配不是新发现的作者裁定。相关原有说明见[粉丝扩展规则](../fan-expansions.md)。

## 检出问题与修复

| 场景 | 检查结果与修复 |
| --- | --- |
| 钱袋单独发动、配合粘液、跨回合、拒绝／无积分、JSON 恢复 | 基础路径原本正常，补组合验证；付费与实际主移动先完成，再响应维尼。 |
| 维尼同时拥有钱袋与其他移动修正 | 飞艇、野兔和派对动物的完成记录可能误标为本体维尼，因排除自响应而漏计。现记录真实技能 ID。补齐 Second Wind 实际生效的修正完成记录；未产生加成的超车者不伪造完成。 |
| 狐狸阻止钱袋 | 狐狸自己的完成记录原先排在等待普通掷骰的 fallback 后，会被 `awaitRoll` 挂住。现先完成狐狸的阻止及响应，再继续被阻止动作的后续。钱袋不返还的费用沿用既有适配。 |
| 维尼与蹭蹭怪／游戏与观看先生同时响应 | 原来分两批 `unshift`，固定让后一批抢先。现构造一个响应列表，合用当前玩家、顺时针、同玩家赛前固定选手顺序；每个响应的子效果先完成。 |
| 公共事件与玩家停格能力 | 原来事件任务带有运动员 ID，会被当作该玩家的能力一起排序。现停格分为可保存的赛道、公共事件、角色阶段。事件引起的新移动先完整结算，之后重新核对仍有效的原落点。 |
| 赛道／事件取代落点 | Bonkbug 或事件飞艇把人带走后，原落点的浪漫家反应仍可能发动。现角色停格任务在前两阶段完成后生成；真实越过仍使用原移动快照。 |
| 多阶段落点与封闭循环 | Boardwalks 箭头加浪漫家事件换牌、游戏与观看先生产生等长队列的真循环；较大的继续任务还会挤掉 96KB 历史中的能力边界。现能力边界允许等长但完整状态／随机／精确 tail 相同的重复判定，缓存优先保留能力与投骰边界。3000／9000 事件保护及 96KB 记录上限均未放宽；独立排队的重复发动继续各自结算。 |

公共事件的优先级是本项目对“赛道优先”在该粉丝事件扩展中的明确适配，公开在[特殊赛事规则](../../public/rules/special-events.md)，不称为原作者针对所有跨包组合的勘误。

## 验证与边界

- 本轮 **24 项**规则组合：含正常／阻止／不发动、同回合计数与复位、复制／获得能力、当前玩家与顺时针／同玩家排序、事件骰三角人反应、NPC 不冒充角色能力、回合开始／停格／回合结束、JSON 恢复、替换落点与真实闭环。
- 完整快速单元／集成测试 **1340/1340** 通过（约 17.8 秒）；已有的所有粉丝包混合 8 人 6 场**纯引擎**固定种子复验通过，包含逐场恢复、公开 AI 和计分平衡。
- 类型检查、客户端／Node 服务端／浏览器主机构建、Worker dry-run 通过。
- 本地 CI=true 软件 WebGL **2/2** 通过：真实点击钱袋付费，先移动再演出维尼且无投骰；公共 NPC 绊倒先于当前玩家浪漫家的技能和移动。演出由操作前安装的浏览器 MutationObserver 留存，并与公开服务器事件 ID 对照。
- 未增加远端 CI 步骤、浏览器矩阵或重复八人大局；24 项必要规则用例由现有单元入口运行。本轮新增浏览器专项只在本地执行。远端 CI／预览以各自实际状态为准。

初轮 15 项组合为 8 过 7 败。落点分阶段后，完整规则发现上表的换牌闭环；先后验证了等长能力边界和历史缓存淘汰策略，没有通过调高保护阈值掩盖问题。最小循环夹具也明确选择 Boardwalks 的相同分支，避免把未选择的分岔当作自动循环。
